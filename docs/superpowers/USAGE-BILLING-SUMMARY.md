## ١. إيه اللي اتعمل / What was built (باختصار)

**الفكرة:** الحصص اللي بتتسجّل في الشهر (يوليو مثلاً) بتتجمّع لوحدها في **اشتراك جديد للشهر اللي بعده** (أغسطس). آخر الشهر، الكرون بيجمّد العدد، يطلّع الفاتورة، ويقفل الشهر. المصدر الوحيد للحقيقة = الحصص نفسها (الرقم **محسوب**، مش بيتكتب مع كل حصة).

| # | الجزء | اتعمل إيه |
|---|-------|-----------|
| A | الأساس | نوع اشتراك جديد `origin = MANUAL / USAGE`. عمود `billedSubscriptionId` على الحصة. دوال تواريخ + دالة حساب الساعات (باختبارات). |
| B | قاعدة البيانات (repo) | استعلامات: مجموع ساعات الشهر، الاشتراك المفتوح، الطلاب النشطين، أقل خطة، تعليم الحصص كـ«مفوترة». |
| C | المنطق | فتح الاشتراك المفتوح أول ما تتسجّل حصة · **الكرون آخر الشهر** (يجمّد + يفوتر + يقفل) · **الكوبون على الاستهلاك** · endpoint العرض الحي. |
| D | الداشبورد | بيرجّع **قائمة اشتراكات** لكل طفل بدل اشتراك واحد. |
| E | الواجهة | chip موحّد للحالة · كارت العدّاد الحي · عمود/فلتر النوع في القائمة · صفحة التفاصيل · كروت ولي الأمر بأكتر من اشتراك. |

**كله اتعمله commit** (١٨ commit)، والـ build بتاع الويب بيعدّي، واختبارات المنطق ٨/٨ خضراء.

## ٢. ⚠️ خطوة واحدة لازم تعملها بنفسك / One manual step (مهم)

الـ schema اتعدّل بس **الـ migration ما اتشغّلش** (زي ما متفقين — مبشغّلش migrate). شغّل ده بنفسك:

```bash
npm run db:migrate -- --name add_subscription_origin_and_billed_session
```

ده بيضيف الأعمدة الجديدة. كل الاشتراكات القديمة هتبقى `MANUAL` تلقائياً (مفيش backfill). **قبل ما تعمل ده، أي تشغيل حقيقي للسيرفر على الداتا هيفشل** — عشان كده التحقق الحي (curl / db studio) متأجّل لحد ما تعمل الـ migrate.

## ٣. إزاي تجرّب بعد الـ migrate / How to test

1. `npm run dev:server` + `npm run dev:web`.
2. سجّل حصتين لطالب في الشهر الحالي → هيتعمل اشتراك `USAGE` بحالة `UPCOMING` (الشهر اللي بعده)، وعدّاده بيكبر.
3. جرّب endpoint العرض الحي: `GET /subscriptions/:id/usage-preview` → بيرجّع الساعات والسعر المتوقع.
4. لتجربة قفل الشهر: اعمل سكربت صغير ينده `subscriptionUsecase.generateMonthlyUsageInvoices(new Date("2026-07-31T23:00:00Z"))` → الاشتراك يتجمّد PENDING + فاتورة + الحصص تتعلّم مفوترة. شغّله تاني → مفيش ازدواج.
5. الكوبون: ولي الأمر/الأدمن يضيف كوبون **عام (مش مربوط بخطة)** على الاشتراك المفتوح أو الـ PENDING (مش ACTIVE) → الخصم بينزل على الفاتورة.

## ٤. قرارات مفتوحة ليك / Open decisions (محتاجة رأيك)

المراجعة النهائية طلّعت نقطتين **قرارات مش أخطاء** — سيبتهم زي ما هما لحد ما تقرر:

1. **الكرون بيفوتر الطلاب اللي عندهم اشتراك ACTIVE بس.** يعني طالب اشتراكه الوحيد هو الاستهلاكي المفتوح (ومفيش عنده ACTIVE حالي) **مش هيتفوتر**. ده مطابق للخطة (اتكتبت «لكل طالب نشط») ومنطقي طالما دايماً فيه اشتراك حالي شغّال. **لو عايز الطلاب «الاستهلاك بس» يتفوتروا كمان، قوللي وأزوّد اختيارهم في الكرون.**
2. **ازدواج نادر:** لو اتسجّلت حصتين لنفس الطالب في نفس اللحظة بالظبط، ممكن يتعمل اشتراكين مفتوحين (واحد بيتجمّد والتاني يفضل فاضي). نادر جداً وأثره تجميلي. **أقدر أحصّنه بقفل transaction لو حابب.**

(كمان نقطة صغيرة: العدّاد الحي بيتحدّث لما تعيد فتح الصفحة، مش لحظياً — كفاية دلوقتي.)
